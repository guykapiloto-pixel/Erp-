# סוכן בדיקת חובות לקוחות – לוח "יעל EK-גבייה"

## ניתוח גבייה מ-Hyp (`debtcheck hyp`) – המסלול הראשי
המסלול משלב שני מקורות. כל אחד מהם עונה על מה שהשני לא יודע:

| מקור | מה יש בו | מה חסר בו |
|---|---|---|
| דוח מסמכים מ-Hyp (`report.csv`) | כל המסמכים מיום הפתיחה: סוג, מספר, תאריכים, לקוח, ח.פ, סכומים ואמצעי תשלום | **סטטוס**: האם חשבון העסקה עדיין פתוח |
| תמונת מצב של הלוח (נתוני Hyp שהלוח מסנכרן) | מסמכים פתוחים לפי מזהה לקוח ב-Hyp, יתרה פתוחה, רשימת לקוחות ואנשי קשר, חיובים אוטומטיים | היסטוריה |

**החוב לגבייה** מחושב כך שחוב לא ייספר פעמיים:
- **קיזוז ברמת הלקוח.** חשבון עסקה נשאר פתוח ב-Hyp גם כשכבר הופקה בגינו חשבונית מס או חשבונית מס קבלה שלא שויכה אליו.
  לכן החוב ללקוח הוא הנמוך מבין: חשבונות העסקה הפתוחים ב-Hyp, והנוסחה (עסקה − מס − מס קבלה + זיכוי) על כל ההיסטוריה.
- **חשבונית מס שפתוחה ב-Hyp** אינה חוב לגבייה אלא פריט לאימות (ניתן לשינוי: `tax_invoice_open_is_debt`).
- **העבודה של יעל בלוח גוברת על החישוב:**
  - יתרה שנבדקה וסומנה תקינה יורדת מהחוב.
  - לקוח בחיוב קבוע לא נספר, אלא אם יש לו חיוב אוטומטי שנכשל וטרם טופל.
  - שיק דחוי שבידינו מנוכה מהחוב.
  - לקוח שתויג לבדיקה מול גיא/דקל לא נכנס לרשימת הפנייה עד שתתקבל תשובה.
  - לקוח שהוסתר בלוח מוחרג.

```bash
python -m debtcheck hyp --config config.yaml --csv report.csv --board <תיקיית תמונת הלוח> --out report.xlsx
python -m debtcheck hyp ... --customer "שם / ח.פ"      # פירוט ללקוח בודד
```
תמונת הלוח היא ייצוא של מסד הנתונים של הלוח (`hyp/*.json`, `custList/*.json`).

**בקרות:**
- סך המסמכים הפתוחים מושווה לסה"כ בלוח.
- כל מסמך פתוח מושווה לקובץ Hyp (מספר + סכום).
- מסמך שמזהה הלקוח שלו בלוח הוא 0 משויך לפי הלקוח שעל המסמך.
- קבלה שלילית (החזר/שיק חוזר) מבטלת את הקבלה המקורית.
- מסמך פתוח שקיים אחריו תשלום באותו סכום מסומן "ייתכן ששולם".
- תשלומים שהתקבלו אחרי עדכון הלוח מנוכים מהחוב.

**מתי לפנות ("רשימת השבוע"):**
- **סדר עדיפויות לקביעת המועד:**
  1. מועד הפנייה הבאה שקבעה מנהלת הגבייה בלוח.
  2. אחרת, פנייה אחרונה ועוד מחזור לפי עדיפות: 7 ימים בדחוף, 14 בלטיפול, 30 במעקב.
  3. לקוח שלא פנו אליו מעולם – היום.
- **לקוח שמשלם בתאריך קבוע** לא נכנס לרשימה לפני יום התשלום ועוד יומיים.
- **הפניות מתפזרות** על ימי העבודה (א'–ה') לפי קיבולת שבועית (`weekly_capacity`), והעודף עובר לשבוע הבא.
- **מוחרגים מהרשימה:** לקוח שהוסתר בלוח ולקוח מוחרג לפי הגדרה.

הרצה בלי `--csv` נשענת על הלוח בלבד: מסמכים פתוחים ותשלומים מ-22/6/2026. בהרצה כזאת אין בקרת נוסחה. ראו `WEEKLY_RUN.md`.

**גיליונות הדוח:** רשימת השבוע · סיכום · למי לפנות · פירוק חוב · נספר כפול · מסמכים פתוחים · בעיות נתונים · שיטה.

## מסלול כללי (`debtcheck run`) – לוח במבנה מסמכים/סיכום

הכלי מחשב לכל לקוח את יתרת החוב, מפרק אותה לפי סוג מסמך ומסדר את הלקוחות לפי דחיפות הפנייה.

## הגדרת החוב
```
חוב = Σ חשבונות עסקה − Σ חשבוניות מס − Σ חשבוניות מס קבלה + Σ זיכויים
```
- **זיכויים** נלקחים בערך מוחלט ומתווספים לחוב (`credit_sign: abs`). אם בלוח זיכוי נרשם במינוס ויש לנכות אותו, מגדירים `as_is`.
- **קבלות, הצעות מחיר ותעודות משלוח** אינן חלק מההגדרה. הן מוצאות מהחישוב ומופיעות בגיליון "בעיות נתונים" כמידע.
- **מסמכים מבוטלים** (לפי עמודת סטטוס) לא נספרים.

## גיול
הלוח לא מציין איזו חשבונית סגרה איזה חשבון עסקה. לכן הכלי מקצה את סך החשבוניות, בניכוי הזיכויים, לחשבונות העסקה **לפי FIFO** (הוותיק נסגר ראשון).
- חשבונות העסקה שנותרו פתוחים הם החוב. התאריכים שלהם קובעים את הגיול: 0‑30, 31‑60, 61‑90, 91‑180 ו‑180+.
- זהו **אומדן**. סכום הגיול תמיד שווה ליתרת החוב, וזה נבדק בבדיקות.

## עדיפויות פנייה (ספים ב-`alerts`)
| עדיפות | תנאי |
|---|---|
| דחוף | חוב ≥ `urgent_amount`, או חשבון עסקה פתוח ≥ `urgent_days` ימים |
| חריג | יתרה שלילית (חשבוניות/זיכויים עולים על חשבונות העסקה), או זיכויים שעולים על סך החשבוניות |
| לטיפול | חוב פתוח ≥ `followup_days` ימים, או חוב ללא תאריך |
| מעקב | חוב שוטף |
| תקין | יתרה אפס (בטווח `min_debt`) |

## בקרות איכות נתונים
אף שורה לא נזרקת בשקט. שורה שלא נספרה מופיעה בגיליון "בעיות נתונים" עם מספר השורה בלוח. הבקרות:
- סוג מסמך לא מוכר, סכום לא קריא או שורה ללא לקוח: **שגיאה, השורה לא נספרה**.
- מספר מסמך כפול (לאותו סוג): **שגיאה**. השורה נספרה, ויש לבדוק כפילות.
- תאריך חסר: השורה נספרה, ללא גיול.
- סכום שלילי במסמך שאינו זיכוי.
- לקוח שנכתב בכמה צורות (`בע"מ`/`בעמ`/רווחים/גרשיים): הצורות מאוחדות, ונרשמת הערה.
- שמות דומים שלא אוחדו (למשל "גמא תעשיות" ו"גמא תעשיה"): **אזהרה**. שמות שנבדלים רק במספר אינם מסומנים.
- אם קיימת עמודת ח.פ./מספר לקוח (`customer_id`), היא משמשת כמפתח במקום השם. זו הדרך המומלצת.

## הרצה
```bash
cd debt_agent
pip install pyyaml openpyxl
cp config.example.yaml config.yaml        # להשלים board_id ומיפוי עמודות

# א. ישירות מ-monday
export MONDAY_API_TOKEN=...               # Profile > Developers > My access tokens
python -m debtcheck inspect --config config.yaml          # רשימת עמודות הלוח, למילוי המיפוי
python -m debtcheck run --config config.yaml --out debt_report.xlsx

# ב. מקובץ ייצוא של הלוח (Export board to Excel) – ללא טוקן
python -m debtcheck run --config config.yaml --file export.xlsx --out debt_report.xlsx

# פירוט מלא ללקוח בודד (לבדיקה מול הלוח)
python -m debtcheck run --config config.yaml --file export.xlsx --customer "שם הלקוח"
```
אפשרויות נוספות: `--as-of YYYY-MM-DD` (תאריך הגיול) ו-`--json out.json` (פלט לאוטומציה).

### מבני לוח נתמכים (`layout`)
- `documents`: כל שורה היא מסמך.
- `documents` + `source.use_subitems: true` (API בלבד): הלקוח הוא הפריט, והמסמכים הם תתי-פריטים. במצב הזה `customer: parent_name`.
- `summary`: כל שורה היא לקוח, עם עמודת סכום לכל סוג מסמך. אין גיול.

- ייצוא monday עם קבוצות ותתי-פריטים.
- עימוד API, עמודות נוסחה וניסיון חוזר בחריגת מורכבות.
